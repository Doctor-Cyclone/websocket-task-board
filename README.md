# WebSocket Task Board

Совместная доска задач на React с синхронизацией между участниками через WebSocket.

## Текущее состояние

Подготовлены React с TypeScript/TSX, Vite, SCSS Modules, ESLint, Prettier, настройки редактора и GitHub Actions. Реализованы подключение и отключение WebSocket, отображение состояния соединения, создание jobs, переключение статуса выполнения и удаление задач. Изменения рассылаются всем подключённым клиентам, а интерфейс обновляется после событий сервера. При подключении клиент получает полный актуальный список. Общие схемы Zod проверяют события и задают их TypeScript-типы.

Интерфейс и сообщения приложения на английском языке. Логика соединения и списка вынесена в хук `useJobs`, серверная рассылка — в `broadcast`. После разрыва соединения клиент автоматически переподключается с задержками 2, 4, 8, 16 и максимум 30 секунд. Disconnect отменяет дальнейшие попытки. После восстановления соединения список загружается заново.

Создание job содержит `requestId`. После обработки сервер отправляет инициатору `request:ack` с тем же идентификатором; подтверждение выводится в консоль браузера. Клиент ждёт ACK до 5 секунд, затем сообщает об отсутствии подтверждения. Полученный ACK отменяет таймер; Disconnect и удаление страницы очищают все ожидающие таймеры.

Создание и обновление jobs используют `requestId`, ACK и ручной Retry при отсутствии подтверждения. Повторные обработанные запросы не применяются второй раз. Отказы сервера показываются в Requests. Версии jobs защищают от устаревших обновлений.

Доски Alpha и Beta изолированы. Клиент хранит последний известный список каждой комнаты до перезагрузки страницы. Сервер сохраняет jobs, версии и обработанные запросы в `server/data/boards.json`, который исключён из Git. ACK отправляется после записи. Хранилище рассчитано на один процесс сервера. Редактирование названия задачи пока не реализовано.

## Тесты

`pnpm test` запускает серверные и клиентские тесты Vitest, `pnpm test:watch` — наблюдение за изменениями. Проверяются операции с jobs, изоляция комнат, дубликаты запросов, конфликты версий, восстановление данных, повреждённые файлы и откат при ошибке записи. Клиентские тесты проверяют переподключение, таймеры ACK, поздние подтверждения, Retry и очистку ресурсов. Они используют управляемые таймеры и имитацию WebSocket; настоящий сервер не нужен. Серверные тесты используют отдельные временные файлы и не изменяют рабочие доски.

`pnpm check` выполняет линтер, проверку форматирования, тесты, проверку типов и сборку. Эта же команда используется в GitHub Actions.

## Запуск

Нужны Node.js 22.13+ (рекомендуется 24) и pnpm 11.25.0.

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

Откройте http://127.0.0.1:5174/. Для остановки нажмите Ctrl+C.

Во втором терминале запустите сервер: `pnpm dev:server`. Он принимает подключения на `ws://localhost:3001`.

## Команды

| Команда             | Назначение                                         |
| ------------------- | -------------------------------------------------- |
| `pnpm dev`          | Запустить разработку с обновлением страницы        |
| `pnpm lint`         | Проверить TypeScript, TSX и правила React hooks    |
| `pnpm lint:fix`     | Исправить автоматически исправляемые замечания     |
| `pnpm format`       | Отформатировать файлы                              |
| `pnpm format:check` | Проверить форматирование                           |
| `pnpm typecheck`    | Проверить типы фронта, сервера и конфигурации Vite |
| `pnpm dev:server`   | Запустить сервер с перезапуском при изменениях     |
| `pnpm build`        | Проверить типы и собрать приложение в `dist/`      |
| `pnpm preview`      | Проверить сборку на http://127.0.0.1:4174/         |
| `pnpm check`        | Выполнить lint, format:check и build               |

ESLint проверяет ошибки и правила React, а Prettier отвечает за оформление. `eslint-config-prettier` отключает конфликтующие правила. В VS Code рекомендуемые расширения указаны в `.vscode/extensions.json`; устанавливаются пользователем.

## Структура

```text
src/
  main.tsx                  # Точка входа React и StrictMode
  app/
    App.tsx                 # Сборка приложения из страниц
    styles/global.scss      # Базовые глобальные стили
  pages/
    board/
      index.ts              # Публичный интерфейс модуля страницы
      ui/
        BoardPage.tsx
        BoardPage.module.scss
server/index.ts     # WebSocket-сервер
shared/protocol/    # Общие схемы Zod и типы событий
tsconfig*.json     # Проверка типов браузера и Node.js
eslint.config.js    # Правила TypeScript и React
vite.config.ts      # Сборка и локальные порты
.github/workflows/ci.yml
```

Компоненты и их `.module.scss` лежат рядом. Классы подключаются через `styles` и изолированы от других компонентов. В глобальных стилях остаются только базовые настройки страницы.

`app` отвечает за сборку приложения, `pages` — за страницы. По мере появления функциональности добавляются `features` для действий пользователя, `entities` для предметных сущностей и `shared` для общего кода. Модули экспортируют доступные снаружи компоненты и функции через `index.ts`; внутренние файлы используются внутри своего модуля.

Точные зависимости закреплены в `pnpm-lock.yaml`. `.env`, зависимости, сборка и локальные настройки JetBrains (`.idea`) не хранятся в Git.
